# jitsuen

実演 — a narrated product demo, built by Claude Code from a brief and a folder of
screenshots and screen recordings.

HyperFrames 0.8.174 + VOICEVOX 0.25.2. `research.md` has the full study; `plan.md` the design
and the implementation checklist. `.claude/skills/demo-video/` drives a build.

Claude Code is the planner and author; every mechanical step is a deterministic script.
`pnpm ingest` → *you author the storyboard* → `pnpm validate` → `pnpm voice` →
*you author `index.html` and `video/scenes/*.html`* → `pnpm check` → `pnpm lint` →
`pnpm studio` → `pnpm render`.

## Layout

`src/` and `scripts/` are the TOOL and are tracked. ONE video is `/index.html` plus
`video/` — brief, storyboard, narration manifest, theme tokens, the authored scene
sub-compositions and the source media — and all of it is gitignored, because a brief and a
narration script are usually the client's. A fresh clone has neither and will not render
until `pnpm new` seeds them from `templates/`.

```
/index.html              AUTHORED, gitignored — root composition: scene mounts, narration, captions
/video/scenes/<id>.html  AUTHORED, gitignored — one <template> sub-composition per scene
/video/tokens.css        AUTHORED, gitignored — theme VALUES
/src/theme.css           tracked — theme MECHANISM
/src/blocks/*.js         tracked — per-scene-type motion helpers
/src/fonts/*.woff2       tracked — the bundled CJK faces
/assets/                 generated by `pnpm ingest` + `pnpm voice` — media, voiceover, fonts, vendor
```

The project root is the repo root. That is forced, not chosen: HyperFrames requires the
entry composition to be `index.html` at the project root, and a composition **cannot
reference anything above its project root** (`invalid_parent_traversal_in_asset_path` is a
hard lint error), so `src/` and `assets/` have to live inside it.

## Never

- Never call an Anthropic API. Claude Code *is* the planner; scripts are deterministic.
- Never run `npm` or `npx`. This project is pnpm-only; versions come from `mise.toml`.
- Never rely on a transitive dependency. pnpm does not hoist; `import` it only if it is in
  `package.json`.
- Never bump `node` or `pnpm` outside `mise.toml`, and never add `shamefully-hoist`.
- Never put pnpm settings in `package.json`'s `pnpm` field — pnpm 11 ignores it with a warning.
  They live in `pnpm-workspace.yaml`.
- Never use `Math.random()`, `Date.now()`, CSS `transition`/`animation`, or `setInterval`
  in `src/`. A render seeks to arbitrary frames in parallel tabs that share no state.
- Never call `play()`, `pause()`, or set `currentTime` on a media element, and never toggle
  `visibility` in a script. The framework owns media playback and clip lifecycle; a script
  that duplicates it fights it.
- Never register a timeline asynchronously. Timeline construction must be fully synchronous
  — no `async`, no `await`, no `fetch` — and the assignment to `window.__timelines` goes
  **last**, after every tween is added.
- Never author a media element without an `id`. An `<audio>` without one is skipped by the
  mixer and **the render comes out silent with no error anywhere** — every automated check
  still passes. `pnpm check` greps for this specifically.
- Never put `data-start` on a `<video>` *and* on a timed ancestor in the same composition
  (`video_nested_in_timed_element`). Inside a scene sub-composition the video's `data-start`
  is local and the host carries the absolute one.
- Never add `crossorigin` to a media element, and never set `data-has-audio="true"` on
  silent footage — use `muted`.
- Never use `data-trim-start` / `data-trim-end` / `data-playback-start`. They are not in the
  schema and are silently ignored; the real attribute is `data-media-start`.
- Never generate scene markup with a loop. One authored node per scene, one per caption.
- Never hoist a timing literal into a variable — Studio write-back needs it on the node.
- Never hardcode a colour, font size or margin in `src/theme.css`. Values come from
  `video/tokens.css`; if a token is missing, add it. A literal in the mechanism file is a
  value the next reference-match will silently fail to change.
- Never put per-video content under `src/`. If it describes one video rather than the tool,
  it belongs in `video/` or `/index.html`, which are gitignored. This is how a client's
  narration script ends up in a public repo.
- Never trust `hyperframes snapshot` to tell you whether footage is present. It screenshots
  the DOM and does **not** run the FFmpeg frame extraction that injects video frames, so
  every `<video>` reads as empty. Only `pnpm render` shows footage.
- Never retry a VOICEVOX HTTP 500 — it means the text broke the phoneme analyzer. Fix the
  text. On 0.25.2 the likelier failure is the opposite: unreadable text returns **zero
  accent phrases** and would synthesize silence, so `synthesize.ts` throws on that instead.

## Always

- A composition's length is **its GSAP timeline's length**. There is no `data-duration` on a
  composition. Every timeline — the master and each scene — ends with
  `tl.set({}, {}, <seconds>)` to carry its full length, or the video is silently truncated
  at the last tween. Six of the ten scenes have no tweens at all; without this they collapse
  to zero.
- Every composition needs a script that creates a paused timeline and registers it under its
  own `data-composition-id`. The framework nests sub-compositions automatically from the
  host's `data-start` — never add them to the parent timeline by hand.
- Time inside a scene sub-composition is SCENE-LOCAL and starts at 0. Only `/index.html`
  holds absolute times.
- `data-track-index` groups the timeline into rows and orders layering; CSS `z-index` is what
  actually paints. Clips on one track must not overlap in time. Scenes are lane 1, narration
  lane 2, captions lane 3.
- Seconds are emitted by `secondsAttr()` in `src/timeline.ts` and nowhere else, floored to
  6 dp, with each duration derived from the *emitted* neighbouring starts. The floor is a
  consistency convention so `pnpm check` has exactly one right answer — the renderer
  quantises seconds back to frames, so it is not guarding a one-frame bug.
- `video/storyboard.json` is the only place `width`, `height` and `fps` are written. They are
  mirrored as literals on the root and `pnpm check` compares them.
- Round each timeline boundary from a running total of seconds. Never sum per-scene
  `Math.ceil` — measured at 27 frames (0.9 s) of drift over a 5-minute video.
- Give every scene host, narration element and caption node a stable `id`. `pnpm check`
  finds them by that and nothing else.
- Paths in HTML (`src`, `data-composition-src`) resolve against `/index.html`, so they are
  **project-root-relative** — `assets/media/x.mp4`, even from inside `video/scenes/x.html`.
  Paths in CSS `url()` resolve against **the stylesheet**, so `src/theme.css` reaches the
  fonts as `../assets/fonts/x.woff2`. Getting this wrong 404s silently and the face falls
  back to a system font — tofu on any machine without a CJK font installed.
- A separate `<script src>` file has no composition to resolve a relative URL against, so
  `src/blocks/*.js` must never construct an asset path. All media lives in the authored
  composition's attributes.
- Motion helpers must be cold-seek safe: set initial state with a bare `gsap.set()` before
  adding tweens, name every destination explicitly, and use no `fromTo`, no relative values
  (`"+="`), and no `getBoundingClientRect()`/`getComputedStyle()` in a callback.
- `.clip` supplies a full-frame box (`top: 0; height: 100%`) along with the
  `visibility: hidden` the runtime toggles. A clip that is not full-frame — a caption, say —
  must reset `top` and `height` itself, or the box is over-constrained, `bottom` is ignored
  and it renders as a full-height column.
- Theme lengths are authored for a 1080px short edge and scaled by `--k`. Write a scaled
  length as `round(calc(var(--size-x) * var(--k) * 1px), 1px)` — the `* 1px` is load-bearing,
  because `round(<number>, 1px)` mixes types and drops the declaration.
- `--vw` / `--vh` must be declared on `:root`, not on `#stage`. Custom properties inherit
  downward only, so `--k` computed on `:root` cannot see a `--vw` set on a descendant, and
  every scaled length silently becomes invalid.
- Check the longest real string against `width − 2 × margin` before raising the type scale.
- GSAP is vendored into `assets/vendor/` by `pnpm ingest`, not loaded from a CDN, so renders
  stay offline and the rendered version is the one in `pnpm-lock.yaml`. A local
  `<script src>` lints clean; no waiver is needed.
- `--workers 1` on a render: each worker is a separate Chrome process, and one keeps the
  output reproducible run to run.
- `hyperframes.json` configures the registry and install paths ONLY. It is not a render
  config — every render option is an explicit CLI flag in `scripts/render.ts`.
- Changing the default look for FUTURE videos means editing `templates/tokens.css`;
  `video/tokens.css` only affects the video in front of you.
- `video/narration.json` is the timing lockfile for the current video. It is NOT tracked.
- `mise.toml` and `pnpm-lock.yaml` are tracked too. Commit lockfile changes separately.
- `assets/` is generated in full. Re-run `pnpm ingest` after adding material and `pnpm voice`
  after changing narration; never edit it by hand.
- FFmpeg and ffprobe are hard runtime requirements and come from `mise.toml`. Run
  `hyperframes doctor` when a render fails for an environmental reason.
- `pnpm validate` → `pnpm voice` → `pnpm check` → `pnpm lint`, in that order.

## Deliberately not adopted

HyperFrames ships two things that look like they replace parts of this pipeline. They are
rejected on purpose; do not "simplify" the pipeline onto them.

- **`hyperframes tts`** (local Kokoro-82M) does not replace `pnpm voice`. VOICEVOX is the
  point: the Japanese voice, the per-character terms archived into
  `out/<project>.credits.md`, and the mora-level timings in `scripts/lib/mora-timing.ts`
  that every caption boundary is derived from. A different engine would mean different
  timings and no character terms.
- **`hyperframes transcribe`** does not replace the caption pipeline. Captions here are not
  transcribed from audio — they are the narration text the human wrote, aligned to the
  moras VOICEVOX reports for that exact text. Transcribing synthesized speech back into
  text would be a lossy round trip of something already known exactly.
